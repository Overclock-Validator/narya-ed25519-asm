# Executable Lean Ed25519 specification

`formal/lean/NaryaSpec` is a runnable Lean 4 definition of the DalekStrict
predicate that Narya implements and Mithril calls through
`narya.VerifyStrict`. It is written for clarity, not speed, and imports only
Lean core: no Mathlib, no foreign code, no `implemented_by`, and no `partial`
definitions. The compiled checker therefore runs the same definitions that
proofs will refer to, and `make check-formal-hygiene` enforces those
restrictions.

## Contents

| File | Definition |
| --- | --- |
| `Bytes.lean` | Little-endian and big-endian byte conventions |
| `Sha512.lean` | SHA-512 as written in FIPS 180-4, one block at a time |
| `Field.lean` | GF(2^255 - 19) as canonical residues; inversion by Fermat; the RFC 8032 square-root ratio |
| `Edwards.lean` | Affine points and the textbook complete addition law; extended-coordinate scalar multiplication; the permissive decoder; canonical encoding; small-order test |
| `Verify.lean` | `verifyStrict`, laid out clause by clause like `VerificationSpine.DalekStrict` |

The decoder is the permissive one used by Go's `crypto/ed25519`,
curve25519-dalek and Agave. It accepts a noncanonical `y` (reduced modulo
`p`) and the sign bit set on `x = 0`. Verification requires a canonical `s`,
rejects small-order `A` and `R`, requires `R` to be canonically encoded, and
checks the cofactorless equation `[s]B - [k]A = R` with
`k = SHA-512(R || A || M) mod L` over the original `R` and `A` bytes.

## Evidence

`make check-lean-spec` runs the compiled checker against every committed
fixture in `tests/vectors`, none of which this code produced:

| Check | Source of expected values | Result |
| --- | --- | --- |
| SHA-512 | FIPS 180-4 examples | 3/3 |
| Curve constants; extended against affine multiples | Standard basepoint encoding; the affine law in this spec | 51/51 |
| `[1]B` to `[128]B` | Python affine big-integer generator | 128/128 |
| Fixed-base scalar multiples | Python affine generator | 256/256 |
| Variable-base signed multiples | Python affine generator | 256/256 |
| Permissive decoder decisions and coordinates | Narya's scalar radix-2^51 decoder, including `p` to `p + 18` and negative zero | 256/256 |
| Scalar reduction mod `L` | Adversarial reduction fixture | 31/31 |
| Independently signed inputs, 0 to 4,096 bytes | Python RFC 8032 signer | 8/8 |
| DalekStrict verdicts | RFC 8032, C2SP CCTV, Wycheproof and derived edge cases, with verdicts from the Go oracle | 2,954/2,954 |

Each verification takes about 3 ms on an Apple M4 Pro laptop.

The fixtures catch plausible specification mistakes. Each of these four
deliberate edits fails the checker:

- dropping the small-order check on `R` (43 verdicts change);
- RFC-strict decoding that rejects a noncanonical `y` (24 decoder rows change);
- rejecting negative zero (3 decoder rows change);
- a cofactored equation, `[8]([s]B - [k]A) = [8]R` (63 verdicts change).

A one-off differential run also compared the spec with Narya's Go oracle
(`crypto/ed25519.Verify` plus small-order rejection) on 18,249 inputs. They
were generated by the shapes of `FuzzR51BackendDifferential`: honest,
corrupted, edge-point `R` and `A`, mixed-order public keys, `s + L`, near-`L`
scalars, repeated lanes, raw random bytes, short signatures and wrong keys.
All verdicts matched, including 430 accepted mixed-order signatures, whose
verdict depends on the challenge modulo the torsion order. That corpus is
not committed; `--verdicts FILE` checks any file in the external-corpus
schema.

## What this does not prove yet

This layer is an executable definition checked by testing. No theorem yet
connects it to `VerificationSpine` or to the native leaves. Remaining
obligations, in order:

1. `Fe` is a model of `ZMod p`: every operation keeps `val < p` and commutes
   with the cast. This needs `p` prime only for the inversion and square-root
   lemmas, which a Pratt certificate can supply.
2. The affine `Point.add` forms an `AddCommGroup` on curve points.
   Associativity is the hard part; a birational map to a Weierstrass model
   is one route.
3. `Ext.add` refines `Point.add`, so `Point.nsmul` equals the group's
   `nsmul`. The checker currently compares them on 46 scalars.
4. `decode` and `encode` are mutually inverse on canonical encodings, and
   `smallOrder` matches `PureSmallOrder`.
5. Instantiating `VerificationSpine.StrictSpec` with these definitions
   turns `verifyStrict_correct` into a theorem about this executable
   predicate; the native leaf proofs then discharge its implementation
   hypotheses one by one.
